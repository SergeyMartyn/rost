## Утверждённое поведение

1. Новая двуязычная RU/DE страница для ведущих, доступная по заметной, но незалитой ссылке «Хочу провести игру» из блока покупки игр. На телефоне сохранить текущую компактную кнопку покупки участника; ссылку ведущего показывать в полном блоке.
2. Радиокарточки форматов: стандартное участие **249 €**, расширенное **349 €**. Независимая галочка «Фото и видео» добавляет **79 €**. Четыре полных суммы: 249/328/349/428 €. Не показывать устаревшие зачёркнутые цены как текущие условия.
3. Независимая галочка «Внести предоплату 50 €»: по умолчанию снята; при выборе меняет **только сумму к оплате сейчас** на 50 €. Полная стоимость остаётся прежней; показывайте остаток (например, 249 → 50 сейчас + 199 позже; 428 → 50 сейчас + 378 позже). 50 € засчитываются в общую стоимость. Если галочка снята, сейчас оплачивается полная сумма. После предоплаты организаторы **вручную** отправляют ссылку на оплату остатка; не обещать автоматическую отправку и не списывать остаток автоматически.
4. Одна крупная кнопка: «Зарегистрироваться и занять стол». Под ней меньшим текстом — актуальная **сумма к оплате сейчас**. Не писать, что весь формат стоит 50 €. Финальная страница платёжного провайдера также должна явно показывать списываемую сумму.
5. Сейчас **7 свободных столов**. Количество задаётся в одном серверном параметре/конфигурации. После отправки заполненной анкеты стол держится **30 минут**, после подтверждённой оплаты закрепляется. При истечении/отмене неоплаченная бронь освобождается, но данные анкеты остаются. Малый объём продаж позволяет простую реализацию, однако не допускайте двойного назначения последнего стола при одновременных запросах. Не добавляйте сложную очередь и систему ручного подтверждения.
6. После подтверждённой оплаты отдельное одобрение организатора **не требуется**. Возврат с Checkout без серверного подтверждения платежа не считается оплатой. Фразу о невозврате предоплаты из показанного сценария убрать.
7. Обращение к заявителю на **«вы»**. Сократите анкету до нужного до оплаты: имя, email, контакт в мессенджере по уже существующему механизму Telegram/WhatsApp/Instagram, название и короткое описание игры, формат и допопции, необходимые согласия. Дополнительные длинные материалы можно запросить позже. Сохраняйте даже неоплаченную заявку. Не сохраняйте данные карты.

## Технические точки в коде

- Маршруты и переводы: `src/lib/site.ts`, `src/pages/[...path].astro`; общий Layout/Header уже есть. Договоритесь об итоговых RU/DE slug до публичного релиза, либо выберите по существующей схеме маршрутов и зафиксируйте в тестах.
- Билет участника и существующее окно покупки: `src/components/EventPage.astro`. Контактный ввод/валидацию можно извлечь для повторного использования; не копируйте две независимые версии правил. Текущую продажу 80/180 €, PayPal/Stripe для участников и архивных событий не ломайте.
- API и вебхуки: `worker/index.ts` маршрутизирует `/api/*` в `worker/orders.ts`; `worker/tickets.ts` — серверный каталог. Создайте отдельные данные/маршруты для заявки ведущего и серверный расчёт суммы (249/349 + 79, платеж 50 либо вся сумма). Не доверяйте цене, присланной браузером. Исторический `host` не удаляйте из обработки старых заказов без миграционного анализа.
- D1: `migrations/0001_orders.sql` — текущие заказы. Добавьте новую нумерованную миграцию для заявки/брони и при необходимости связи с оплатой. Минимальные состояния: ожидает оплаты, оплачено, бронь истекла/отменена. Изменение доступного места должно быть атомарным на уровне БД, а не отдельным `SELECT count` и последующим незащищённым `INSERT`.
- Stripe Checkout для текущих билетов в `worker/orders.ts` истекает через 35 минут. Для заявки ведущего выставьте 30 минут и освобождайте стол при истечении; проверьте поздние вебхуки, повторную доставку и асинхронный платёж. Если поддерживаете PayPal для ведущих, не допускайте capture после истечения брони без повторной проверки места. Не меняйте существующее поведение PayPal/Stripe участника.
- Нужно отдельно оформить RU/DE условия именно для ведущих и путь к политике конфиденциальности. Текущие `src/components/ParticipationTerms.astro` описывают участников. Не выдумывайте срок внесения остатка, налоговый режим и правила отмены. Эти пункты требуют согласования с владельцем **до боевого запуска**, даже если макет и тестовая оплата готовы.
