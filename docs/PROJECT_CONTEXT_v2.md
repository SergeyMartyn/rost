Сайт двуязычный (RU/DE). Пиши естественно на каждом языке, сохраняй смысловую парность. Не переноси слова механически и не разрывай обычные русские и немецкие слова дефисами ради вёрстки; исправляй локально ширину, размер или расположение текста. Пользователь участвует в проекте как совладелец с долей 40%; решения по позиционированию, публичным обещаниям, ценам, правовым данным и выпуску принимает владелец с командой. ## 4. Маршруты и выпуск

В `site.config.json` установлены `name: R.O.S.T.`, `domain: https://rost.community`, `defaultLanguage: ru`, `workerName: rost`. Домен в конфиге служит для URL/метаданных; сам по себе он не доказывает доступность или актуальность опубликованного сайта.

| Страница | DE | RU |
| --- | --- | --- |
| Главная | `/de/` | `/ru/` |
| Мероприятия | `/de/veranstaltungen/` | `/ru/meropriyatiya/` |
| О нас | `/de/ueber-uns/` | `/ru/o-nas/` |
| Контакты | `/de/kontakt/` | `/ru/kontakty/` |
| Impressum | `/de/impressum/` | `/ru/pravovaya-informatsiya/` |
| Datenschutz | `/de/datenschutz/` | `/ru/konfidentsialnost/` |

`getStaticPaths()` создаёт обе языковые версии шести страниц. `/` — запасной ручной выбор языка; Worker при запросе `/` выбирает язык по cookie `site_language`, затем `Accept-Language`, затем `defaultLanguage`, и отвечает 302 без кэширования. Прямые локализованные пути Worker отдаёт Static Assets без языкового перенаправления. Тот же route map используется в ссылках, переключателе языка, canonical/hreflang и sitemap. После изменения конфига, путей или контента нужна новая сборка.

Команды: `npm ci`, `npm run dev`, `npm run check`, `npm test`, `npm run build`, `npm run preview`, `npm run test:browser`, `npm run config:check`. `npm run deploy` запускает технические проверки и публикацию; его не вызывают для обычной локальной проверки. В ограниченном окружении `npm test` и build могут вернуть `spawn EPERM` из-за запуска дочерних процессов. 28 сентября после разрешённого повтора **check: 0 ошибок/предупреждений; unit: 4/4; build: успешно, 14 страниц**. Это подтверждает локальный код, не внешний релиз и не визуальное качество. Для browser-тестов по умолчанию нужен Microsoft Edge (см. `playwright.config.ts`).

- Главная: `Hero`, `Events`, `Formats`, `Faq`. Страница мероприятий: один `EventPage.astro` с двумя секциями — встреча в Регенсбурге 10 октября 2026 и игры в Мюнхене 14 ноября 2026. Отдельных URL для отдельных событий пока нет.
- Страницы «О нас» и «Контакты» существуют как короткие страницы в catch-all компоненте. «Контакты» ведут на `mailto:` из конфига; контактной формы в коде нет.
- Hero: CTA ведёт на мероприятия; кнопка видео отключена, видео не подключено.
- Главные карточки событий уже используют **локальные реальные изображения** в `public/images/` и полноразмерный просмотр через `<dialog>`. Они пока не отслеживаются Git. Версия 1 ошибочно называет все фото плейсхолдерами. На странице мероприятия отдельные графические блоки/места могут ещё быть временными — проверяй конкретную секцию.
- В мобильном меню иконки Instagram, YouTube, Telegram сейчас `<span>`, без внешних ссылок. Не выдумывать адреса профилей.
- Ticket UI в `EventPage.astro`: выбор билета, имя и контактный канал (Telegram, Instagram, WhatsApp с номером или именем пользователя), локальная валидация, переход ко второму экрану, чекбокс согласия и кнопки PayPal/Stripe. **Оплата и сохранение данных не подключены.** `submit` перехватывается в браузере, кнопки оплаты только разблокируются чекбоксом; обработчика платежа нет. Не называть билеты продаваемыми через сайт и не подключать платёжный сервис без отдельной задачи.
- Текущие цены в интерфейсе после решения владельца 29 сентября 2026: 29 € за встречу, 99 € для гостя игр, 249 € для ведущего игр. Время и точный адрес в текущем event UI указаны как уточняемые.
- `src/lib/services.ts` содержит пустой список. Consent-баннер и кнопка настроек скрыты, пока нет опциональных сервисов. Перед внедрением аналитики, внешнего видео, карт и прочего нужно согласовать интеграцию, обеспечить загрузку только после согласия и синхронизировать правовые тексты.

1. `README.md` и `docs/BRIEF_FOR_ASTRO_TECH_SPEC_v5.md` описывают исходный **нейтральный Astro-шаблон**, а не полностью актуальную продуктовую спецификацию R.O.S.T. Они полезны для техники, но не определяют сегодняшние тексты и дизайн.
2. `docs/DESIGN.md` и `../DESIGN.md` относятся к референсу Niti Caring Camp. Визуальные значения R.O.S.T. проверяй по текущим `src/styles/*.css`, компонентам и `design/`. Не заменяй существующую тему значениями из Niti без задачи.
3. `../Structure_v1.md` — ранний план страниц и блоков. Часть идей, например отдельные страницы событий и история/команда, ещё не реализована. План не является описанием готового сайта.
4. В папке `../2026.10.10 - Regensburg/` есть разные рабочие документы с **расхождениями** по цене (29/30 €), времени, вместимости и программе. В коде сейчас 29 €, а время/адрес уточняются. Для новой публичной формулировки сначала выясни актуально утверждённый командой источник; не считай любую заметку приказом изменить сайт. Холодную аудиторию для пилота считай отдельно от знакомых и существующего сообщества. Целевые CAC и количество участников — гипотезы/критерии теста, не достигнутые результаты.
5. `site.config.json` содержит заполненные операторские данные и правовые тексты, но правовой текст упоминает контактную форму, регистрацию и возможные сторонние сервисы, которых в текущем сайте нет. Это **расхождение содержания с реализацией**, а не вывод о юридической корректности. До публикации новой функциональности или изменения правового текста требуется содержательная проверка владельцем/специалистом. Не придумывай правовые формулировки.
6. `PROJECT_CONTEXT.md` (v1) описывает Git до `c091436`, ошибается в составе WIP и фото. Используй этот файл как более поздний снимок, но всегда сверяй статус заново.
