# Задача: создать нейтральный двуязычный шаблон сайта на Astro

Создай и проверь **новый проект с нуля в папке проекта, где лежит этот файл**. Этот документ — задание на реализацию, а не запрос на ТЗ. Сначала осмотри содержимое папки и действуй в её пределах. Не используй файлы, Git-историю, названия, домены или дизайн других проектов. Не выполняй push и публикацию.

## Цель и стек

Нужен переносимый стартовый проект для небольших будущих сайтов: скопировать в новую папку, задать параметры сайта, подключить новый Git-репозиторий и Cloudflare и начать работу над содержанием. **Выбранный стек — Astro, TypeScript и Tailwind CSS v4**. Сайт собирается в статические файлы. Другой фреймворк не используй. Держи реализацию небольшой и понятной.

## Обязательное ядро

- Русская и немецкая версии: минимальные шапка, главная страница, футер, Impressum и Datenschutz. Правовые страницы — только каркас с явно незаполненными полями; готовые юридические тексты и выдуманные данные не нужны.
- Адаптивная вёрстка для телефона, планшета и десктопа: подход mobile first, обычные пороги `md`/`lg`, разумные отступы, ограничение ширины контента и небольшой единый набор дизайн-токенов. Доступность с клавиатуры, видимый фокус, читаемый текст, отсутствие горизонтальной прокрутки и разрыва слов внутри RU/DE текста.
- Постоянные адреса `/ru/` и `/de/`. Немецкие пути — немецкие слова, русские — согласованная латинская транслитерация. Одна явная таблица соответствующих страниц должна задавать внутренние ссылки, переключатель языка, canonical, `hreflang` и sitemap. Переключатель ведёт на перевод текущей страницы, если он есть.
- При входе на `/` язык выбирается по настройкам браузера с учётом приоритетов `Accept-Language`; при ручном выборе учитывается предпочтение пользователя. Для других языков — настраиваемый язык по умолчанию. Автоматический выбор действует **только на `/`**: прямые ссылки на локализованные страницы никогда не переадресуются по языку браузера. Для статического сайта на Cloudflare предусмотри минимальный Worker для этого входного маршрута и доступные ссылки на оба языка в запасной корневой странице.
- SEO-основа: уникальные метаданные по языкам, canonical, `hreflang`, sitemap, robots, корректная 404, базовые favicon и изображение для предпросмотра ссылок. Пустые или примерные домен, название и правовые данные должны блокировать публикацию, но не мешать локальной проверке шаблона.
- Готовый двуязычный модуль согласия: баннер, равнодоступные «Принять», «Отклонить», «Настроить», выбор необязательных целей, сохранение и отзыв выбора через футер. Необязательные сервисы и сторонние ресурсы не загружаются до согласия. В чистом шаблоне таких сервисов нет, поэтому баннер не показывается; модуль включается и проверяется при их добавлении.
- Конфигурация нового сайта без чужих имён и доменов: название, домен, язык по умолчанию, маршруты, имя Cloudflare Worker. Секреты не хранятся в шаблоне. Чётко раздели параметры сборки статических страниц, переменные Worker и полномочия Wrangler.

## Результат и проверка

Создай рабочие файлы проекта и краткую инструкцию по созданию нового сайта из чистой копии. Зафиксируй точную таблицу RU/DE адресов, правила языка и ссылок, настройку параметров и границы статической сборки. Проверь сборку, ответы 200/404, языковой вход и переключение, SEO-метаданные, адаптивность, работу consent-модуля при его включении и отсутствие сторонних запросов до согласия. Проверь, что шаблон работает после копирования в новую папку без локальных секретов и временных файлов.

Не добавляй CMS, формы, аналитику, PWA или другие функции без отдельной задачи. В конце кратко сообщи, что создано, какие проверки прошли и что владелец должен заполнить перед первым выпуском. Если что-то не удалось проверить, назови точную причину. Не подменяй реализацию перечнем предложений.
